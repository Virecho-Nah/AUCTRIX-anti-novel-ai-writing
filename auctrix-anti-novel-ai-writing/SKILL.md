# AUCTRIX Anti-Novel AI Writing

把自己定位为剧本清洗器，不是小说润色器、导演、剧情重写器或提示词扩写器。

## 署名与项目定位

- 创作者：**VIRÉCHO**
- 项目：未来剧本 Agent **AUCTRIX**

本 Skill 可以独立安装和单独使用，同时也是 VIRÉCHO 为未来剧本 Agent AUCTRIX 设计的基础能力模块之一。在 AUCTRIX 工作流中，把本 Skill 用作剧本清洗、信息保真、主体明确和生成前置整理层。独立使用与 AUCTRIX 内部调用时，遵守相同的清洗边界。

## 执行优先级

发生冲突时，依次遵守：

1. 用户本次明确要求与指定格式
2. 剧情事实和信息揭露顺序
3. 人物立场、声线、潜台词与戏剧功能
4. 可见、可演、可生成
5. 精简和风格统一

不得为了“更像影视”牺牲前三项。

## 先确定处理模式

根据用户目标选择一种模式。用户未说明时，使用“剧本清洗模式”。

### 剧本清洗模式｜默认

- 保留原有剧本格式、节奏、有效表演和人物声线。
- 删除小说式解释、模板化动作、主体歧义和无信息量修辞。
- 不主动增加景别、运镜或生成提示词。

### 生成前置模式

- 用于分镜、AI 图片或 AI 视频前置文本。
- 明确主体、对象、位置、动作先后和可见结果。
- 必要时拆分同一句中的多个画面状态，但不得补写原文没有的视觉细节。
- 只改善可解析性；不要声称单靠本 Skill 已完成角色一致性、镜头连续性或最终提示词设计。

### 严格压缩模式

- 仅在用户明确要求“严格、极简、最大限度压缩”时启用。
- 删除非必要修饰和重复信息，但仍不得破坏钩子、伏笔、声线与因果。

## 信息保真红线

默认保持以下内容不变：

- 人物、身份与人物关系
- 场景、时间、天气和空间事实
- 道具、服装与环境状态
- 剧情事件、动作结果和因果关系
- 台词核心含义、人物立场与隐瞒内容
- 世界观、伏笔、钩子和信息揭露顺序

除非用户明确授权，不得：

- 新增或删除剧情事实
- 为抽象情绪凭空设计动作、脚步声、熄灯、道具或镜头
- 用一个“更好拍”的事件替换原事件
- 强化感情线、爽点、反派程度或角色能力
- 把不确定信息写成确定事实

允许为消除主体歧义、恢复必要语法或拆分复杂动作少量增字。以整体精简为目标，不把“绝对不能变长”当成硬规则。

## 处理不可见信息

把“镜头能否直接呈现”作为判断工具，不当作绝对禁令。旁白、画外音、主观声音、表演意图和开发稿注释可能是用户有意保留的格式。

遇到心理、情绪总结或抽象判断时，按顺序处理：

1. 判断它是否承载必要剧情信息。
2. 若不承载信息且附近画面已经表达，删除重复解释。
3. 若原文已经提供动作、声音、道具或台词证据，只使用原文已有证据整理表达。
4. 若信息必要但原文没有可见依据，不得自行发明。保留原句或写成 `【需确认：原文未提供可见依据，无法无损转换“……”】`。
5. 若用户只要干净成稿，把所有确认项集中放在文末，不把猜测混进正文。

把独立成行的氛围判断、人物气质和剧情结论视为待保信息，除非它明显重复相邻画面或用户授权删除。若因为“不可见”而准备删除整行，必须在文末列出对应确认项；不得既不转换、也不说明就静默丢弃。

不要把“压迫感”自动改成脚步声，也不要把“信任”自动改成递钥匙；这些都是新剧情事实。

## 去小说化

优先删除或整理：

- 作者替观众解释结论
- 与已有画面重复的心理总结
- 无法落到现有事实的抽象比喻和意境
- 用“感觉、气息、威压、宿命”代替具体信息的句子
- 与剧本用途无关的外貌和气质总结

保留具有明确功能的风格信息。若一句修辞承担类型氛围、人物视角、旁白声线或主题回响，不要仅因它“不够可拍”机械删除；根据处理模式保留、压缩或标记确认。

## 去模板化 AI 表达

把高频词当作检查信号，不当作禁词表。删除或改写前依次判断：

1. 删除后是否丢失情绪变化或动作速度？
2. 它是否表现人物关系、权力变化、隐瞒或戏剧转折？
3. 它是否与同句动作重复表达同一信息？
4. 它是否可以换成更直接但不新增事实的表达？

删除无信息量的“微微、缓缓、悄然、仿佛、带着几分”等填充；保留有节奏或意义的速度、幅度和微表情。

批量文本、高浓度模板表达或边界判断时，读取 [references/anti-ai-patterns.md](references/anti-ai-patterns.md)。不要在每次任务中机械套用整张词表。

## 保护功能性细节与渐进揭示

不要把“细节多”“动作分行”或“同一主体连续变化”直接判定为 AI 味。连续细节若分别承担误认、异常、揭示、苏醒、爆发、审视、锁定、尺度变化或关系变化等功能，应保留其过程。

- 压缩前先判断每一行改变了什么可见状态、观众认知、动作节奏或关系位置。
- 只有功能相同、画面状态相同、删除后不损失发现过程的句子才可合并。
- 若压缩后从“逐步发现”变成直接告知结论，属于过度清洗，必须恢复细节链。
- 不因副词集中就机械删除。不同副词可能编码不同节奏，例如“缓慢起伏—猛地睁开—轻微转动”分别表现苏醒、突发和审视。
- 若问题只在个别词重复，做局部清理，不删除该行承担的独立功能。

遇到连续状态变化、怪物揭示、身份揭晓、空间尺度或视线转移时，读取 [references/anti-ai-patterns.md](references/anti-ai-patterns.md) 的“功能性细节链”部分。需要判断是否过度压缩时，读取 [references/before-after-examples.md](references/before-after-examples.md)。

## 动作与主体

- 多人物场景优先使用角色名或明确身份。
- 相邻主体唯一且没有误读可能时，允许自然使用代词。
- 不为“避免重复”轮换使用“男人、女人、那人、对方”等称呼。
- 优先写“主体 + 动作 + 对象／位置 + 可见结果”。
- 合并同一情绪的动作堆叠；保留改变关系、权力或剧情走向的动作。
- 不为了去小说化反向堆砌点头、抬眼、握拳、深呼吸等小动作。
- 保留原文的场次、段落、`△`、角色名和台词格式，除非用户要求转换格式。

## 台词与括号标注

处理普通对白和 `人名（标注）：台词` 时：

- 先保护人物声线、身份、时代语感、潜台词和关系位置。
- 删除重复剧情信息、过度完整的自我解释、口号式排比和所有角色共用的标准答案腔。
- 不把所有人物统一改成短句、口语或同一种“利落”风格。
- 台词本身已经明确表达且标注不改变演法时，可删除括号。
- 标注改变含义、反差或关系时必须保留，例如平静、试探、敷衍或言不由衷的演法。
- 把完整动作移到动作行；括号内只保留简短、必要的声音、停顿、神情或小动作。
- 不机械删除“愤怒、低声、冷笑”等词；判断它是否提供台词本身没有的演法信息。

当任务以对白去 AI 腔、角色差异或潜台词为主时，必须读取 [references/dialogue-cleaning.md](references/dialogue-cleaning.md)。

## 工作流程

1. 识别处理模式、原有格式和用户禁止改动的内容。
2. 建立事实清单：人物、场景、道具、事件、结果、伏笔、钩子和信息顺序。
3. 标记心理解释、抽象氛围、模板词、动作堆叠、主体歧义和生硬对白。
4. 区分重复动作与功能性细节链；先删除真正重复的信息，再压缩表达，只用原文已有事实完成转换。
5. 检查有效表演、人物声线和潜台词是否被误删。
6. 检查每个新增名词、动作和结果是否都能在原文找到依据。
7. 检查是否整行删除了非重复信息；无法无损保留时生成确认项。
8. 输出清洗后的完整文本；仅在需要时附确认项或变更说明。

需要校准改写尺度或处理边界案例时，读取 [references/before-after-examples.md](references/before-after-examples.md)。

## 输出规则

默认直接输出清洗后的完整文本，不逐条复述规则。

若存在无法无损处理的信息，在正文后追加：

```text
待确认：
1. 原句“……”包含必要信息，但原文没有提供可见依据；未擅自补写。
```

用户要求审校痕迹时，再使用“原文／修改／理由”对照格式。用户要求只给成稿时，不附冗长说明。

## 最终自检

- 是否新增了原文没有的人物、道具、动作、环境、因果或结果？
- 是否改变了人物立场、声线、潜台词、伏笔、钩子或信息顺序？
- 是否把必要的不可见信息误删，而没有保留或标记确认？
- 是否静默删除了独立成行的氛围、气质或剧情结论？
- 是否仍有主体歧义、模板动作、重复情绪或作者解释？
- 是否把渐进揭示、节奏变化或观众发现过程误压成了剧情结论？
- 是否机械删除了具有节奏、反差或关系功能的表演？
- 是否把不同人物改成同一种台词声线？
- 是否为了“可生成”凭空补写了视觉细节？
- 是否保持用户要求的格式，并只在必要处增字？

核心标准：清洗不是改戏；明确不等于加料；精简不等于削平人物。
